# 新产品规格书上传与处理

> 适用：向 ATERag 导入新的产品型号规格书（Markdown）。
> MCP 服务现常驻板卡 192.168.5.25:8080（systemd `aterag-mcp`），`registry.yaml` 的权威副本在板卡 `/opt/aterag/registry.yaml`。

## 一览

```powershell
$env:BOARD_SSH_PASSWORD='<板卡密码>'
$env:PYTHONIOENCODING='utf-8'
.venv\Scripts\python.exe scripts\upload_new_spec.py "D:\docs\PN2000-24A 定制电源技术规格书.md"
```

一条命令完成：前置校验 → 上传到板卡 → 板卡执行全链路导入 → 重启 MCP → 同步注册表回开发机。

## 前置要求（规格书必须满足，否则导入失败或质量下降）

| 要求 | 规则 | 来源 |
|---|---|---|
| 格式 | **仅支持 Markdown**（`.md`/`.markdown`），UTF-8 编码 | `ingest_spec` 以 `utf-8` 直读 |
| 型号 ID | 文档**前 500 字符**内出现形如 `PA601-D54A` / `PN2000-24A`（2~8 位大写字母 + 数字 + `-` 分段） | `ingest_spec` 正则 `\b([A-Z]{2,8}\d[A-Z0-9]*(?:-[A-Z0-9]+)+)\b` |
| 版本 | 前 800 字符内含 `版本: A`（可选，缺失则 `doc_version` 为空） | `ingest_spec` 正则 `版本[:：]\s*([A-Z0-9.]+)` |
| 标题 | 首行为 Markdown 标题（`#`），否则章节树与分块质量下降 | 解析器依赖标题层级 |
| 需求表头 | 表含 `编号 / 项目 / 单位 / 最小值 / 最大值 / 等级` 等列 | `entity_extract` 锚点右对齐抽取 |

Word / Excel 需先转换为 Markdown（当前管道不含 docx/xlsx 解析，见交付报告"遗留建议"第 2 条）。

## 上传前先做 dry-run

```powershell
.venv\Scripts\python.exe scripts\upload_new_spec.py "D:\docs\PN2000-24A.md" --dry-run
```

只做前置校验与上传，不执行导入。型号识别失败会直接拦截并说明缺什么。

## 导入后会自动发生什么

`ingest_spec` 全链路（`src/aterag/ingest/pipeline.py`）：

1. **型号识别** — 从标题提取 `model_id`
2. **产品类型分类** — LLM 判定 `power` 等 domain；新 domain 自动建域
3. **注册** — 写入 `registry.yaml`（`kb_status` / `doc_version`）
4. **解析** — Markdown → 章节块（章节树 + 过滤路径）
5. **实体抽取** — 需求 / 保护 / 信号 / 产品，含 `min/max/rail/priority/section_path`
6. **落库**（**全部落在 PostgreSQL**，无第二套存储）
   - PostgreSQL `aterag_entities`（**按 (model_id, etype) 先 DELETE 再全量 INSERT** —— `pipeline.py:92/100`。注意这使摄取**结构上不可能产生双源**，冲突消解因此没有第二个来源可比）
   - PostgreSQL `aterag_chunks`（**重导前先清空该 workspace 旧分块**，`pipeline.py:113`，幂等覆盖）；向量列即 pgvector `vector` 列，与 BM25 索引（`bm25 (content)`，`pipeline.py:71`）同表
   - sidecar `rag_storage/blocks/{model_id}.jsonl`
   - **不再有 Qdrant / LightRAG**（ADR-014 已整层退场）。向量检索走 pgvector，全文走 `pg_textsearch` + `zhparser`，两者由 `src/aterag/retrieval/hybrid.py` 做 RRF 融合 —— 该模块自称「全系统唯一的检索实现」。`chunk_key` + 唯一索引保证重复导入幂等（`pipeline.py:171-180`）
7. **重启 MCP 服务** — 注册表在服务启动时加载，新型号不重启会"导入成功但查不到"

## 常用运维

```bash
# 板卡侧查看已注册型号
ssh <board_user>@192.168.5.25 "cat /opt/aterag/registry.yaml"

# 上传后的规格书原件
ssh <board_user>@192.168.5.25 "ls -l /opt/aterag/specs/"

# 重启 MCP（手工改了 registry.yaml 后必做）
ssh <board_user>@192.168.5.25 "sudo -n systemctl restart aterag-mcp"
```

## 已知限制

| 限制 | 说明 |
|---|---|
| 仅 Markdown | Word/Excel 需先转换 |
| 相对路径依赖 CWD | CLI 已 `os.chdir(APP_ROOT)` 固化；若自写脚本须注意 `.env` / `registry.yaml` / `domain_rules` / `rag_storage` 全部相对 CWD 解析 |
| 注册表单一权威源 | 板卡为权威；开发机副本由 `upload_new_spec.py` 自动同步，**不要**在开发机手改 `registry.yaml` |
| 型号 ID 唯一 | 同型号重复导入按幂等覆盖处理（`DELETE` + `chunk_key` 唯一索引），不会产生重复数据 |
| 重复导入无簿记残留 | 旧实现经 LightRAG 会新增 `dup-*` 文档记录；该层已按 ADR-014 移除，现在重复导入只体现为 `DELETE` + 重插，无额外残留 |
| 无版本回滚 | 重导直接覆盖，无历史版本留存；需保留旧版请自行归档规格书原件 |
