## 一、不齐次 7 条

### 1. `F_J.8.3_VDS_SPIKE` —— **方案错误**(置信度高)

```
原文    : ΔV_spike ≈ I_pk·L_lk·f_sw/C_oss
方案量纲: [A]·[H]·[Hz]/[F] = [V]
实测    : L⁴M²T⁻⁷I⁻³,与声明的 V 不符
```

**判定:方案错误。** 依据是纯量纲算术,与外部文献无关:

- `A·H·Hz = I·(V·s/A)·(1/s) = V` —— **精确成立**
- 所以 `I_pk·L_lk·f_sw` 已是电压,末尾的 `/C_oss` 是**多余项**
- 方案自己写的 `[A]·[H]·[Hz]/[F] = [V]` 在算术上就是错的:
  `V/F = V²/C`,而 `[V²/C] = L⁴M²T⁻⁷I⁻³ ≠ [V]`

**外部佐证**:MOSFET 制造厂应用笔记(Rohm / Infineon / Toshiba)描述 Coss 尖峰
由 **dv/dt 给 Coss 充电 + 主回路电感谐振**决定,给出的是等效电路与
`Qoss = ∫Coss(V)dV` 积分式,**没有** `I·L·f/C` 这一形式。

**建议**:删除 `/C_oss`,改为 `ΔV_spike ≈ I_pk·L_lk·f_sw`。请作者确认。

### 2. `F_J.8.1_SHOOT_THROUGH` —— **方案错误(疑缺死区时间因子)**

```
原文    : I_shoot = V_bus/(2·L_par)
方案量纲: [A]
实测    : T⁻¹·I(= A/s),不是 A
```

**判定:公式缺一个时间因子。** 寄生电感换流模型下,死区期间母线电压加在
`L_par` 上,电流斜率 `di/dt = V_bus/L_par`,故峰值电流
`I = V_bus·t_dead/L_par`。方案式子缺 `t_dead`,量纲差一个 `[s]`。

**外部佐证**:公开文献(Fairchild AN-6003、Infineon、Maple)算直通电流用
**跨导模型** `I ≈ K_GM·(V_STEP(MAX) − V_TH(MIN))`,与本式**不是同一模型**。
两个模型各自成立、适用条件不同(跨导模型适用于驱动器 dv/dt 诱导的误开通;
寄生电感模型适用于换流回路)。

**建议**:请作者确认意图 —— 若为寄生电感模型则补 `t_dead`;若为跨导模型则
整式替换。不要由我方代填。

### 3. `F_J.6.2_DCM_PEAK_CURRENT` —— **方案错误(疑多余因子)**

```
原文    : I_pk = sqrt(2·P_out·L·f_sw/(D²·V_in))
实测    : 含 质量^0.5,不是电流
```

**判定:疑似多余因子。** 量纲算术:关系 `P = ½·L·f·I_pk²` 给出
`I_pk = sqrt(2·P_out/(L·f_sw))`,而 `[P/(L·f)] = [A²]`,开方即 `[A]` —— **自洽**。
方案式子多了 `D²·V_in`,量纲由此失衡。

**注意**:此处结论来自量纲推导,**未经文献确认**,可信度低于前两条。
请作者核对 DCM 峰值电流的标准关系式。

---

### 4. `F_S.5_EFFICIENCY_CURVE` —— **方案错误(名称/量纲与自身公式不符)**

```
原文    : P_opt ≈ sqrt(P_fixed·R_load)
方案量纲: [W]
实测    : V
```

**判定:方案错误。** `sqrt(W·Ω) = V` —— 精确等于**电压**,不是功率。
最大功率传输里 `V = sqrt(P·R)`(电压)、`P_max = V²/R`(功率)是两条不同的式子。
方案把电压的式子命名为 `P_opt` 并声明 `[W]`。

**建议**:二选一 —— 改名为 `V_opt` 并声明 `[V]`,或改为功率式 `P_opt = P_fixed`。

---

### 5. `F_W.1.10_NORTON` —— **我方错误**(符号碰撞)

```
原文    : I_N = V_th/R_th, R_N = R_th
期望    : I_N 为电流
实测    : V/(K/W) —— R_th 被解析成「热阻」
```

**判定:我方错误。** 诺顿等效中的 `R_th` 是**等效电阻 `[Ω]`**(Thevenin/Norton
resistance),不是热阻。U.5 收录的 `R_th` 是热阻 `[K/W]`,而解析按 U.5 命中,
于是把电阻当成了热阻。

**建议**:为诺顿语境单独声明 `R_th`(命名空间隔离),或改用不碰撞的符号
(如 `R_north`)。**不要**改全局 `R_th` 的量纲 —— 热阻那个是对的。

### 6. `F_L.5.6_PFH_1001D` —— **我方错误**(LHS 提取)

```
原文    : PFH ≈ λ_DU·T_proof
实测    : 右侧 = 无量纲 [1]  ✓ 正确
误报    : 「声明的结果量纲 = T⁻¹」
```

**判定:公式本身正确,是我的 LHS 提取错。** `λ_DU`[1/T] × `T_proof`[T] = 无量纲,
而 PFH(1001D)本就无量纲。是校验器取了 `λ_DU` 单变量当 LHS。

**建议**:修 `check_homogeneity` 的 LHS 提取 —— 左侧是乘积时应**求积**而不是
取首个变量。**公式无需改动。**

### 7. `F_W.6.13_RESOLUTION_TIME` —— **分类错误**(散文被当公式)

```
原文    : 需 t_resolve ≈ 1 个时钟周期,否则用同步器
归一化  : 1        (无量纲常数)
```

**判定:不是公式。** 这是设计指引散文,右侧被归一化成常数 `1`。

**建议**:改判为规则/指引,移出公式库。这是抽取器的分类问题。

## 二、引擎判不了 10 条 —— 全部是**引擎能力缺口**,公式本身未发现错误

引擎白名单只有 `{sqrt,abs,min,max,exp,ln,log,log10,integral}`,不认
**用户自定义的函数式符号**,也不认连乘记号。

| 公式 ID | 中文名 | 拦路记号 |
|---|---|---|
| `F_K.6_FILTER_CRITERION` | Middlebrook 判据 | `Z_in(f)` 输入阻抗函数 |
| `F_M.1.8_TUR_RANGE_DEPENDENT` | TUR 推荐/量程依赖 | `TUR(R_L)` 总利用率 |
| `F_N.3.1_MLCC_DC_BIAS` | — | `k(V_DC)` 降额函数 |
| `F_N.4.9_PARALLEL_SYSTEM` | — | `Π(1-R_i)` 连乘 |
| `F_S.2_DERATING_CURVE` | — | `η(V_in)` 效率函数 |
| `F_W.6.10_TIMING_CLOSURE` | 时序收敛判据 | `t_logic(...)` |
| `F_W.7.19_SOA` | 安全工作区 | 语法 Tuple |
| `F_W.11.13_ANTIALIAS_FILTER` | 抗混叠滤波器 | `H(f)` 传递函数 |
| `F_W.12.6_HAZARD_RATE` | 危险率(失效率) | `f(t)` 失效率函数 |
| `F_W.12.12_PARALLEL_SYSTEM` | 并联系统 | `Π(...)` 连乘 |

**两类子问题**:

1. **函数式符号**(8 条):`η(V_in)`、`Z_in(f)`、`k(V_DC)` 等 —— 物理上是
   **无量纲的传递函数**(随自变量变化的比值)。可处理:声明为「无量纲函数」,
   引擎按其**返回值无量纲**处理。这是**扩展项,不是错误**。
2. **连乘记号** `Π`(2 条):`1-Π(1-R_i)`。需展开为乘积形式或引擎支持 Π。
   `F_W.7.19_SOA` 的 Tuple 报错需单独看(可能同类)。

**建议**:这 10 条**不进公式库**,但也不必改方案 —— 在
`quantity_rules` 侧声明「函数式符号一律无量纲」即可放行。
工作量集中在引擎,与方案无关。
