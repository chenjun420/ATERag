# ADR-013 嵌入向量维度统一为 1024 (`halfvec`)

- 状态: Accepted
- 日期: 2026-10-03
- 关联: V6.0 §2.3、§2.5.1、§3.5.2、§18.3.1；ADR-002

## 背景

V6.0 方案对嵌入维度给出了两个互斥的数字：

- §2.5.1（`定制电源…V6.0.md:474`）、§2.3 表（`:10028`）、§3.5.2 DDL（`:852`）、
  §3.9 对象表（`:2332`）以及部署参数表（`:1728`、`:2095`）一致规定
  **1024 维**，且存储类型一律是 `halfvec(1024)`。
- §18.3.1 的 `formula_embedding` DDL（`:14661`）写的是
  `embedding vector(4096)  -- Qwen3-Embedding-8B`。

Qwen3-Embedding-8B 的**原生**维度确实是 4096（`:1622` 权重表），但同一节
（`:1628`）也写明它支持 MRL，`dimensions` 参数可在 32~4096 之间动态截断。
所以 4096 与 1024 描述的是同一模型的两个不同配置，方案在 §18.3.1 处
误把原生维度当成了部署维度。

这不是纯文档瑕疵。`vector(4096)` 与 `halfvec(1024)` 在 PostgreSQL 里是
**两个不兼容的列类型**：`halfvec` 是 `vector` 的 2 字节降精度投影，
两者之间没有隐式转换。如果照 §18.3.1 建表，`formula_embedding` 与
`doc_chunk` 将无法共享同一套距离算子与同一套 HNSW 参数，检索层的
RRF 融合（§18.2.3）在类型层面就断了。

ATERag 仓库自身对此也没有共识：`README.md` 称 1024 维，
`deploy/qdrant/init_tenant.py:22` 默认 `VECTOR_SIZE=2560`，
`.env.example:20` 注释 `2560`。三处互相矛盾，且
`models/embed_client.py:109-113` 是运行时探针实测，从不硬编码——
也就是说部署事实上依赖调用方传参，任何写死的数字都只是注释。

## 决策

1. **全系统嵌入维度固定 1024**，由 `Settings.embed_dim` 单点声明，
   启动时探针实测并与声明值不符则**启动失败**（不再静默接受）。
2. **所有向量列统一 `halfvec(1024)`**，距离算子统一 `halfvec_cosine_ops`，
   与 §2.3「统一向量存储规范」一致。`formula_embedding` 不再例外。
3. **公式 embedding 与文档 embedding 分表、分 HNSW 索引，但同维度同算子**——
   §18.3.1「注意与文档 embedding 分开」的意图是**召回空间隔离**
   （公式卡文本 vs 文档切块文本的分布不同），用分表实现，而不是用维度隔离。
4. `docs/` 记录本条为对 §18.3.1 的**实施勘误**（不改方案原文）。

## 理由

备选方案与否决理由：

| 备选 | 否决理由 |
|---|---|
| 公式用 4096，文档用 1024（照 §18.3.1 原文） | 两套维度 = 两套 HNSW 参数 = 两套运维口径；且公式检索的收益来自结构化公式卡文本，不来自更高维度。1024 维在公式这种短文本上召回已饱和（Qwen3-Embedding 的 MRL 截断损失在 >512 维后很小）。 |
| 全部升到 4096 | `halfvec` 的全部收益来自降精度存储（§2.3 表格「存储省」）。4096 维下 `vector` 类型单列 16 KB，`halfvec` 优势消失，且 HNSW build 时间与内存翻 4 倍。方案在部署参数表（`:1728`）明确按 1024 算预算。 |
| 保留运行时探针、不固定 | 探针是必要的（要验证 MMaaS 侧确实按 `dimensions=1024` 返回），但**不能作为唯一约束**。当前状态就是纯探针，结果是 README/脚本/`.env` 三处数字漂移，且没有任何一处会因漂移而报错。固定声明 + 探针校验，两者都要。 |

## 影响

- 正面:
  - `formula_embedding` 与 `doc_chunk` 可共享距离算子与融合逻辑，
    §18.2.3 的 RRF 在类型层可用。
  - 探针与声明值不符时启动失败，消除「重建 Qdrant 才发现维度变了」
    这类运行期事故（旧 `DELIVERY-REPORT.md:249` 记录过这个坑）。
  - 三处互相矛盾的文档数字收敛为一处声明。
- 负面 / 代价:
  - 若嵌入服务方不传 `dimensions=1024`，接入会直接启动失败。
    这是有意的 fail-closed：维度错了就该在启动时炸，不该在检索时静默降质。
  - 公式检索召回上限受 1024 维约束。若日后实测 Recall@10 不达标，
    需另开 ADR 推翻本条，而不是在代码里加特例。
- 后续需要做的:
  - `deploy/qdrant/init_tenant.py` 随 ADR-014 一并删除。
  - `.env.example` 的 `#EMBED_DIM=2560` 改为 `EMBED_DIM=1024`。
  - `README.md` 的 1024 维表述改为指向本 ADR。
