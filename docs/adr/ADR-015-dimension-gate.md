# ADR-015 量纲齐次性作为公式入库的硬门禁

- 状态: Accepted
- 日期: 2026-10-03
- 关联: V6.0 原则二、§18.3.1、§18.7.1 G1、§18.9；A-11

## 背景

方案要求每条公式携带 7 维量纲向量（`formula.dimension_vec`，
`NUMERIC(8,4)[]`），且 `dimension_ok` 为入库判据；G1 门禁要求
量纲不齐的公式不得进入知识库（`定制电源…V6.0.md:14627-14628`、§18.9）。

ATERag 现状无法实现这条：`src/aterag/inference/engine.py:106` 和 `:187`
用 `eval()` + 正则黑名单（`_DENY_RE` @:33、`_SAFE_ENV` @:17-31）执行规则里的
`derive.expr`。这条路径**没有任何量纲概念**——它只知道数值，不知道单位。

后果不是「少一个功能」，而是**规则库里已有的公式无法区分对错**。
`P = U*I` 与 `P = U*I*R` 在 `eval()` 下都是合法表达式，都会算出数，
但后者量纲错误（功率×电阻）。这类错误在数值上完全可能落在合理区间，
人工抽检发现不了，一旦流进产测判据就会造成漏判。

§18.10 注 3 也点明了顺序问题：量纲补在事后，会产生大量
「看起来对但量纲错」的公式，因为写的时候没有校验。

## 决策

1. **量纲校验前置于内容生产**。`solver/symbolic.py`（pint 注册表 +
   7 维量纲向量 + `DimensionError`）必须先于 `formula` 表装载完成。
   这是硬顺序，不是建议。
2. **入库门禁 fail-closed**：`formula.dimension_ok = false` 的行
   **拒绝**进入 `formula_embedding`（不进向量索引），并在
   `docgen/validate` 的 G1 中计为错误而非警告。
   `dimension_ok` 列本身保留（§18.3.1 有此列），用于记录
   「已判定为不齐但保留为知识条目」的边缘情形，但**不豁免向量索引**。
3. **替换 `eval()`，不新增第二套求值路径**。`engine.py` 的
   `eval()` 与 `extract/scenarios.py:496-530` 的 `_safe_eval` 都要退场，
   统一走 `solver/symbolic.py`。理由见下表。
4. **7 维向量是可校验的，不是可标注的**。`dimension_vec` 由
   表达式经 pint 推导后与符号声明比对，不一致即 `dimension_ok=false`。
   不接受人工填写的量纲向量绕过推导。

## 理由

| 备选 | 否决理由 |
|---|---|
| 保留 `eval()`，旁边加一层量纲检查 | 两套求值语义必然漂移。`eval()` 的 `sqrt`/`pow` 对量纲是隐式的，`pint` 是显式的；同一表达式在两条路径给出不同错误行为时，无法判断该信哪个。且方案原则二要求「数值/单位/区间判定全部出 LLM 之外」，`eval()` 没有单位就不是「出 LLM 之外」。 |
| 只把 `engine.py` 换成 pint，保留 `scenarios.py` 的 `_safe_eval` | `_safe_eval` 是 AST 白名单求值器，比 `eval()` 的正则黑名单安全得多，值得留作**参考实现**；但它同样无量纲。场景展开里的 `load_derivation` 公式（如 §6 的负载推导）也是公式，必须进量纲体系，否则规则侧有量纲、场景侧无量纲，两边的「公式」同名不同义。 |
| 用 sympy 量纲消元代替 pint | sympy 的 `sympify` + `simplify` 能做符号恒等，但**单位语义弱**：`dim` 只能给出量纲指数，SI 前缀（`mV` vs `V`）要自己处理，而方案 §6.2 术语表大量使用工程前缀。pint 的注册表直接覆盖。且方案 A-11 要求的 7 维向量本质就是量纲指数向量，pint 的 ` dimensionality` 直接给出。两者应当**配合**：pint 管单位与量纲，sympy 管符号化（`expr_ast` 字段、§18.3.1 要求「等价归一用」）。 |
| 允许人工标注 `dimension_vec` 绕过推导 | 门禁失效。人工标注正是 §18.10 注 3 警告的失败模式。 |

## 影响

- 正面:
  - G1 门禁可实现，W1 验收判据「≥400 条公式全部 `dimension_ok=true`」可验证。
  - 量纲错误在**入库时**被拦截，而不是在产测漏判后被追溯。
  - 规则侧与场景侧共用一套求值语义，「公式」一词在全系统含义统一。
- 负面 / 代价:
  - 现有 117 条 YAML 规则里 39 条带 `derive.expr`，其中必然有一部分量纲不齐
    （旧的 `rules_selftest.py` 只能验数值，对量纲无能为力）。
    迁移时需要逐条处置：改正 / 标注 `dimension_ok=false` / 降级为 `UNKNOWN`。
    这是真实工作量，不可跳过。
  - pint 冷启动约 100~300 ms（默认注册表加载）。需惰性初始化 +
    进程内单例，避免每次调用重复加载。
  - 引入 sympy 后依赖体积显著上升（sympy 及其依赖约 50 MB）。
- 后续需要做的:
  - 定义 7 维向量到 QUDT/pint 量纲的映射表（A-11 的具体化），
    写入 `seed/dimension_vocabulary.csv`，并加 G1 门禁校验。
  - 39 条 `derive.expr` 的量纲处置清单需要单独一轮，
    产出与 §18.3.1 勘误列同结构的 `errata`。
